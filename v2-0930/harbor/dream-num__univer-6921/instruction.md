The sheet table UI needs several behavior polish fixes to make table controls consistent and testable.

In `SheetSkeleton`, the default gap colors derived from the theme primary color are currently too strong. When no explicit `defaultBackgroundColor` or `defaultStripeColor` is provided in the gap config, `gapConfig.defaultBackgroundColor` should default to `rgba(r, g, b, 0.025)` and `gapConfig.defaultStripeColor` should default to `rgba(r, g, b, 0.08)`, where `r`, `g`, and `b` come from `themeService.getColorFromTheme('primary.500')`. Explicitly provided colors must still be preserved.

The `OpenTableFilterPanelOperation` in `packages/sheets-table-ui` should not directly manage the filter panel opened context flag or skip work when the panel is already marked open. For valid params and an existing table from `TableManager.getTable(unitId, tableId)`, it should always delegate to `SheetsTableComponentController.openOrToggleFilterPanel` with `{ unitId, subUnitId, row, tableId, column: col }` and return `true`. It should continue to return `false` when params are missing or the target table cannot be found.

Sheet table names need a shared validation API exported from `@univerjs/sheets-table`. Add `validateSheetTableName(name: string, existingNamesSet: Set<string>)`, returning `{ valid: true }` for valid unique names and `{ valid: false, reason }` otherwise. Empty or whitespace-only names should return reason `'empty'`. Names that fail the existing custom-name character rules, start with invalid characters such as a number, contain spaces such as `'Sales Table'`, or duplicate an existing table name case-insensitively should return reason `'invalid'`. The related result types should also be exported.

The default table theme palette should be updated so the first default table theme uses a lighter second row background. In the generated default table theme config, `tableThemeConfig[0].style.secondRowStyle.bg.rgb` should be `'#EEF2FF'`.

When a table range grows to include new columns, automatically generated column display names should use the localized `sheets-table.columnPrefix` instead of the hard-coded English prefix `"Column"`.

The sheet table row/column command API should support direct insertion and removal at a specific index inside an existing table, and these commands should be registered and exported from `@univerjs/sheets-table`. The new commands should include row insertion at an index, column insertion at an index, and column removal at an index. They should validate missing params, invalid counts, missing command targets, missing or mismatched tables, and out-of-range indexes by returning `false`. For valid operations, they should update the table range/column metadata, move affected trailing cell ranges as needed, execute the corresponding mutations through the command service, and push undo/redo information for the workbook unit.

Additional UI utility contracts covered by the tests: add the sheet-table UI helper module used by the table controls tests, including the menu geometry and action helper functions for row and column controls. The table filter panel UI should expose row and column menu buttons in the tested locations and invoke the corresponding row/column insert and remove commands with the expected workbook, worksheet, table, row, column, and count parameters.
