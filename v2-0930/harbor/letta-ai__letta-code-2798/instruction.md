The local “extensions” feature has been renamed to “mods”, but the codebase still exposes many public/internal APIs, paths, option names, test discovery entries, runtime fields, and user-facing messages using the old “extension” terminology. This causes imports and tests that expect the new “mod” names to fail, and it leaves visible CLI/listener behavior referring to “local extensions” instead of “local mods”.

Update the TypeScript codebase so local extension functionality is consistently exposed as mods. Modules and imports under `src/extensions` should be moved/renamed to `src/mods`, with exported types, functions, and registry APIs renamed accordingly, for example `ExtensionAdapter`/`createExtensionAdapter` should become `ModAdapter`/`createModAdapter`, extension event/context/capability types should become mod equivalents, extension tool and permission registry APIs should become mod APIs, and PI provider registry files should be renamed from `pi-provider-extension-*` to `pi-provider-mod-*`. Existing behavior should remain the same after the rename: mod tools, commands, lifecycle events, permissions, provider registrations, OAuth credentials, and model resolution should continue to work.

All call sites must use the new mod terminology. This includes CLI app wiring, tool execution context parameters such as `modEvents`, slash command routing metadata such as `modCommand`, approval classification via mod permission registration, listener runtime state using `modAdapter`, and listener adapter helpers such as `createListenerModAdapter`, `createListenerModContext`, `ensureListenerModAdapter`, `reloadListenerModAdapter`, and `disposeListenerModAdapter`. The listener adapter should expose provider-only capabilities through `LISTENER_MOD_CAPABILITIES`, accept `globalModsDirectory`, load mod files from that directory, and keep the same capability restrictions as before.

User-facing strings should also use “mod” terminology. For example, resolving an unregistered model provider should report: `Model provider "<provider>" is not registered. Load or repair the provider mod, or choose another model with /model.` The remote `/reload` command should reload the listener mod adapter and return `Reloaded settings, local mods, and agent secrets`. PR title examples and comments should no longer refer to local extensions where they mean mods.

Test and coverage scripts should discover tests under `src/mods` instead of `src/extensions`, and renamed test files/imports should compile against the new mod APIs. The refactor should be terminology-only from a behavior perspective: existing functionality formerly provided by local extensions must continue to operate under the new local mods names.
