Add a runtime task for changing the default font and text size used by renderers.

Applications should be able to request a change of font defaults through a new `font::set_defaults` task. The task must allow setting both the default `Font` and default text size (`Pixels`) used by newly created and existing renderers. When this task is executed in the winit runtime, the stored renderer defaults should be updated, all existing window renderers should be recreated with the new defaults, all user interfaces should be relaid out with the recreated renderer, and affected windows should be redrawn. This should make the change visible immediately without requiring the application to restart or reopen windows.

Font-related runtime actions should be grouped under a font action namespace instead of being represented as separate top-level runtime actions. Existing font loading and listing behavior must continue to work through this namespace: loading a font still sends the result through the provided channel, and listing fonts still returns the compositor’s available font families.

Renderer configuration should distinguish renderer-specific settings from compositor/window backend settings. The default font and default text size belong to `core::renderer::Settings`, with defaults of `Font::DEFAULT` and `Pixels(16.0)`. Antialiasing and vsync belong to compositor settings. Conversions from application `core::Settings` should preserve the configured font, text size, antialiasing, and vsync values in the appropriate settings type.

The renderer construction APIs should accept the renderer settings object rather than separate `default_font` and `default_text_size` parameters. In particular, the headless renderer API should be `renderer::Headless::new(settings: renderer::Settings, backend: Option<&str>)`, and compositor renderer creation should accept `renderer::Settings` so windows can be created and recreated with the current defaults.

The testing utilities and simulator/emulator should construct headless renderers using `core::renderer::Settings` derived from `core::Settings`. They should no longer special-case `Font::DEFAULT` to `"Fira Sans"`; the configured default font should be passed through unchanged. When the `fira-sans` feature is enabled, the embedded Fira Sans font should still be registered as the sans-serif family in the graphics font system so default font resolution works correctly.
