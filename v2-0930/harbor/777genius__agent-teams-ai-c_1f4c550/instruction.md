The team provisioning prompt that is sent to headless agents needs stronger cross-team coordination guidance. In the post-compact lifecycle prompt generated by `TeamProvisioningService`, the “Communication protocol” section already describes when to use `cross_team_send`, `cross_team_get_outbox`, and the golden formats for cross-team requests and replies, but it does not clearly instruct agents how to behave when they receive cross-team work.

Update the provisioning instructions so that agents handling cross-team requests do not remain silent from their own team’s perspective. When a cross-team request arrives, the agent should first emit a brief plain-text status update visible in its own team’s Messages/Activity, such as accepting the request and indicating it is investigating or delegating. The prompt should also state that the canonical progress trail for cross-team work must be team-visible first, using plain text updates, task comments, and task state changes so the agent’s own team can see what is happening.

The same communication protocol should also clarify that replies should go back to the requesting team when there is a concrete answer, decision, blocker, or status update, and that agents should not default to messaging `"user"` for cross-team coordination unless the human explicitly asked to be kept informed or the update is clearly relevant to the human.

This text must be present in the provisioning prompt generated during the post-compact lifecycle, alongside the existing cross-team guidance such as “Golden format for cross-team replies”, “Do NOT use cross-team messaging when your own team can answer”, and “resolve it through your own task board and teammates first”.
