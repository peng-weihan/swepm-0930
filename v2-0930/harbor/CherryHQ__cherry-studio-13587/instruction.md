The backup and LAN transfer cleanup behavior needs to be updated for the new backup system while preserving compatibility and improving path safety.

Cherry Studio backups should use a new direct backup format, version 6, that stores the app’s data directories directly instead of relying on the old nested serialized backup structure. Backups must include the relevant Electron user data such as IndexedDB, Local Storage, and the app Data directory, and backup metadata should identify the format as version 6. Restoring a version 6 backup should prepare the restored directories so they are applied on the next app startup, then relaunch the app. On startup, before the main window is created, the app should detect pending restore directories named `IndexedDB.restore`, `Local Storage.restore`, and `Data.restore` under the appropriate user data locations, replace the active directories with those restored versions, and clean up safely if restoration fails.

Existing legacy backups must remain restorable. Older `.zip` backups and `.bak` backups that contain the previous serialized JSON backup payload should still return that JSON data to the renderer so the existing `handleData` flow can process it. The renderer restore flows for local files, WebDAV, Nutstore/WebDAV, S3, and local backup directories should distinguish between a direct backup restore, which returns no JSON and triggers an app restart, and a legacy restore, which returns JSON that must be parsed and imported.

LAN transfer backup support should be exposed as a distinct legacy-backup operation. The IPC channel for deleting LAN transfer backups should be named `backup:deleteLanTransferBackup`, and the main-process API should be `BackupManager.deleteLanTransferBackup(...)`, not the old temporary-backup naming. This deletion API is used to remove files created for LAN transfer under the temporary LAN transfer backup directory, such as paths beneath `/tmp/cherry-studio/lan-transfer`.

The LAN transfer delete operation must be path-safe. It should only delete paths that resolve inside the LAN transfer directory. It must return `true` when an existing valid file or directory inside that directory is removed, return `false` when the target does not exist, and return `false` without calling `fs.remove` for invalid or unsafe paths. It must reject directory traversal and prefix attacks, including examples such as `/tmp/cherry-studio/lan-transfer/../../../../etc/passwd`, `/etc/passwd`, `../../../etc/passwd`, `/tmp/cherry-studio/lan-transfer/../backup/secret.zip`, `/tmp/cherry-studio/lan-transfer-evil/file.zip`, and `/tmp/cherry-studio/lan-transferx`. Valid paths may include nested subdirectories, trailing slashes, duplicate slashes, spaces, and special characters, as long as their normalized resolved path remains inside the LAN transfer directory.

Add a reusable file utility `resolveAndValidatePath(basePath, relativePath)` that resolves a candidate path against a base directory and throws `Invalid file path: path traversal detected` if the resolved path is the base directory itself or escapes the base directory. It should accept normal relative paths such as `file.txt`, `subdir/file.txt`, and `./file.txt`, and reject empty strings, `.`, and traversal such as `../etc/passwd` or `../sibling`.

The factory reset operation should also go through the backup/data management layer so it can safely clear the app Data directory in the context of the new backup and restore lifecycle.

Finally, the Electron store `config.json` should be stored under the app `Data` directory rather than directly under `userData`, so it is included in backups. Existing installations with `userData/config.json` should migrate automatically to `userData/Data/config.json` without losing settings.
