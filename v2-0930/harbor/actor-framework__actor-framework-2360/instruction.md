The CAF serialization layer is being refactored so that JSON readers and writers expose the typed text-reader/text-writer interfaces through the same inspector abstraction used by binary serialization. The goal is to let generic inspection code work with concrete serializers/deserializers through `as_serializer()` and `as_deserializer()` instead of depending on direct `value`/`list` overload calls on each implementation.

As part of this refactor, `serializer` and `deserializer` must provide the generic sequence and value handling needed by derived inspectors, including support for `std::vector<bool>`. Binary serialization of `std::vector<bool>` should preserve round-trip behavior while packing boolean values compactly into bytes. A vector with eight booleans should serialize as the length plus one packed data byte, and vectors with one, eight, nine, or zero elements must deserialize back to the original values.

The base `serializer` contract should remain usable by subclasses that only implement the primitive hooks. Calls to associative-array helpers, key-value-pair helpers, and `value(std::vector<bool>)` must delegate to the virtual primitive operations and propagate failure correctly. Implementations whose primitive value hook fails must report failure for these compound helpers, while implementations whose primitive value hook succeeds should accept even-length boolean vectors and reject odd-length vectors according to the existing serializer test contract.

Keep the public serialization behavior compatible for existing binary and JSON users while moving JSON-specific internals behind the text interface PIMPL design. The target serialization and serializer tests must continue to run through the existing CMake build and CTest selection.
