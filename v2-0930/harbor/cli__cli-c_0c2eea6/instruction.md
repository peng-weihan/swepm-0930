Many REST and HTTP request paths in the CLI are built by hand with `fmt.Sprintf`, string concatenation, or partial `url.PathEscape` calls. This allows variable components such as owners, repository names, branch names, tags, workflow paths, secret/variable names, environment names, and server-returned path fragments to introduce additional path segments or otherwise change which API resource is addressed. For example, deleting a branch named `owner/branch#123` currently constructs `repos/OWNER/REPO/git/refs/heads/owner%2Fbranch%23123`; the fixed behavior should treat the full ref prefix plus branch name as a single path component and request `repos/OWNER/REPO/git/refs/heads%2Fowner%2Fbranch%23123`. Similarly, workflow content paths such as `.github/workflows/flow.yml` must be requested as `repos/OWNER/REPO/contents/.github%2Fworkflows%2Fflow.yml`, and Git refs such as `tags/v2.0.0` must be requested as `git/ref/tags%2Fv2.0.0`.

Introduce an internal `safeurl` package to centralize safe URL construction for these request paths. It should expose a `SafeURL` interface with `String() string`, mutable and immutable implementations, builders for joining path components with and without an already-formed host/prefix, and a way to entrust already-formed URLs. Builders must percent-encode each supplied path component when rendered so that slashes, spaces, `#`, and other special characters inside a component cannot affect the URL structure. Query parameters must be supported without manual string concatenation and must be encoded correctly.

The path builders must reject any component that is exactly `..` and return an error that callers can surface at command level, because percent-encoding does not neutralize a literal `..` segment as path traversal. A component that is already encoded as `%2e%2e` must not bypass this check; it should be treated as ordinary input and rendered double-encoded, for example `foo/bar/%252e%252e/baz`. A single-dot component `.` is allowed and must be preserved verbatim rather than collapsed, including leading dot components such as `././foo/bar`. Empty components should produce empty path segments, e.g. joining `""`, `"bar"`, `""` should render `/bar/`.

`safeurl.JoinPathWithHostPrefix` must preserve trusted host or REST prefixes while safely appending encoded components. Examples of expected rendering include joining host prefix `https://host` with `foo`, `bar`, `%2e%2e`, `baz` as `https://host/foo/bar/%252e%252e/baz`, and joining `https://host` with `foo`, `bar`, `.`, `baz` as `https://host/foo/bar/./baz`.

Add validation for repository strings used as `OWNER/REPO` values. A helper such as `safeurl.RepoPartsFromNWO` should accept exactly one slash separating a non-empty owner and repository name, return the unescaped owner and name, and reject empty input, missing owner, missing name, no separator, or extra slash-separated segments such as `foo/bar/codespaces`.

Update REST and HTTP request call sites across the API layer and command packages so that variable path components are built through safe URL objects and requests pass `safeurl.SafeURL.String()` directly to `api.Client.REST`, `api.Client.RESTWithNext`, `net/http.NewRequest`, `net/http.NewRequestWithContext`, and `net/http.Client` request helpers. Existing behavior such as pagination, query parameters, server-returned URLs, and command-level error propagation must be preserved. URLs already returned by GitHub, such as pagination links or selected-repositories URLs, may be entrusted as immutable safe URLs but should not be reconstructed by hand.

Add CodeQL enforcement for this convention. One query should flag HTTP request URL arguments that are not directly the result of a `safeurl.SafeURL.String()` call, covering `api.Client.REST`, `api.Client.RESTWithNext`, `net/http.NewRequest`, `net/http.NewRequestWithContext`, and `net/http.Client` `Get`, `Head`, `Post`, and `PostForm`. A second query should flag calls to `safeurl.NewImmutableSafeURL` whose argument is tainted by local string assembly such as `fmt.Sprintf`, `fmt.Sprint`, `fmt.Sprintln`, or string concatenation, since immutable safe URLs are an escape hatch intended only for already-formed trusted URLs.
