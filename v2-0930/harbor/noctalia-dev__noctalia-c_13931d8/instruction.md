Noctalia's launcher needs first-class support for config-driven dmenu-style providers. Users should be able to define `[shell.launcher.dmenu.entry.<id>]` tables whose command is executed through the shell, whose stdout lines become launcher candidates, and whose entries can optionally provide an exec template, prefix, label, glyph, and global-search participation flag. Output lines must split a tab-delimited subtitle from the title while preserving the raw line as the selection value.

Add a `DmenuProvider` implementation that loads command output lazily once per launcher session, enforces a timeout and output-size limit, fuzzy-filters results, caps result count, and activates a result by either running the configured exec command with `{selection}` substituted or copying the selected raw line to the clipboard when no exec command is configured. Application startup and configuration reloads must register, clear, and refresh `dmenu.` providers without disturbing built-in or plugin providers.

While adding this feature, move launcher-specific settings out of `shell.panel` into a dedicated `shell.launcher` configuration table. The schema, settings registry, session provider, launcher panel layout/style logic, and config round-trip tests should all use the new `shell.launcher` fields for categories, icons, compact mode, app grid, session search, and usage sorting, while panel placement remains under `shell.panel`.
