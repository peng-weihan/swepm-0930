The application currently assumes a single hard-coded 3MF export target, effectively Bambu Lab H2D with BambuStudio-style configuration, and does not expose printer or slicer choices as first-class settings. This prevents users from selecting other supported printer models or slicer software, and generated 3MF files may use the wrong printer profile/template when the user intends to export for a different machine or slicer.

Add support for printer model and slicer software selection throughout the app. User settings should include persistent fields for the selected printer and slicer, with backward-compatible defaults of `printer_model: "bambu-h2d"` and `slicer_software: "BambuStudio"` on the backend, and `printerModel: "bambu-h2d"` on the frontend settings store. The frontend settings store must provide a way to update `printerModel`, persist it to the existing `lumina-settings` localStorage entry, restore it correctly, and ensure repeated changes leave both store state and persisted state equal to the last selected printer ID. Valid Bambu printer IDs include `bambu-a1-mini`, `bambu-a1`, `bambu-p1p`, `bambu-p1s`, `bambu-x1c`, `bambu-x1e`, `bambu-h2d`, `bambu-h2d-pro`, `bambu-h2s`, `bambu-p2s`, and `bambu-h2c`.

The backend should expose supported printer and slicer metadata for the UI. Add `GET /api/system/printers`, returning a success response with a `printers` array. Each printer entry should include `id`, `display_name`, `brand`, `bed_width`, `bed_depth`, `bed_height`, `nozzle_count`, `is_dual_head`, and `supported_slicers`. Add `GET /api/system/slicers`, returning a success response with a `slicers` array of `{ id, display_name }` entries. Supported slicer IDs should include `BambuStudio`, `OrcaSlicer`, `SnapmakerOrca`, and `ElegooSlicer`.

3MF generation must use the selected printer model and slicer software from `user_settings.json` when choosing export/profile data. If the settings file is absent, incomplete, or unreadable, generation should continue using the default `bambu-h2d` and `BambuStudio` values rather than failing. The selected values should be passed through the conversion pipeline so the 3MF writer can select the appropriate printer/slicer template.

The printer profile registry should cover the supported printer models and be able to return the appropriate template file for a given slicer, falling back to the default template when a slicer-specific template is unavailable. Bambu printers should support BambuStudio by default and OrcaSlicer where an Orca template exists; Snapmaker and Elegoo profiles should expose their corresponding slicer support. The 3MF profile/template files required by these supported combinations should be present so exports can be generated for the advertised printer/slicer selections.
