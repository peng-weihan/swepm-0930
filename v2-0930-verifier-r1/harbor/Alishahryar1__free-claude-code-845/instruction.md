Refactor the provider transport layer so transport families live under package directories in `providers/transports/` instead of the top-level `providers` package, while preserving existing provider behavior and stream/error contracts.

The OpenAI-compatible chat transport currently exposed as `providers.openai_compat.OpenAIChatTransport` should be moved to an OpenAI chat transport package and exposed from `providers.transports.openai_chat`. The package should provide a thin `OpenAIChatTransport` base for providers using OpenAI-compatible `/chat/completions` APIs, while keeping streaming, tool-call assembly, retry/recovery, request preparation, model listing, timeout/proxy handling, and provider-specific hooks working as before. Tests and external code should be able to patch the OpenAI client and HTTP client at `providers.transports.openai_chat.transport.AsyncOpenAI` and `providers.transports.openai_chat.transport.httpx.AsyncClient`.

The native Anthropic messages transport currently exposed as `providers.anthropic_messages.AnthropicMessagesTransport` should be moved to an Anthropic messages transport package and exposed from `providers.transports.anthropic_messages`. The package should preserve support for providers using Anthropic-compatible `/messages` APIs, including model listing from `/models`, native request construction, streaming in Anthropic SSE format, HTTP status/error handling, rate limiting, retry behavior for retryable errors, recovery events, and cleanup. Tests and external code should be able to patch its rate limiter at `providers.transports.anthropic_messages.transport.GlobalRateLimiter`. Recovery helpers that are used directly by tests should be importable from the new package, including `providers.transports.anthropic_messages.recovery.AnthropicMessagesRecovery`.

Remove the old top-level transport modules `providers/openai_compat.py` and `providers/anthropic_messages.py`. No project code or tests should import from `providers.openai_compat` or `providers.anthropic_messages` after the refactor. All concrete providers that previously inherited from these transports, including OpenAI-compatible providers such as NVIDIA NIM and native Anthropic-compatible providers such as Wafer and Zai, should import the transport classes from the new package locations and continue to behave the same.

OpenAI chat tool-call handling should be split out into an importable component under the new OpenAI chat transport package. Code that needs to assemble OpenAI tool calls should be able to use `providers.transports.openai_chat.tool_calls.OpenAIToolCallAssembler`. This assembler must preserve the previous behavior for emitting Anthropic-style tool-use SSE events, handling chunked tool call names and arguments, buffering Task tool arguments, forcing Task `run_in_background` to `false`, tolerating malformed tool JSON on flush, handling missing or negative tool indexes without crashing, emitting `input_json_delta` events, restoring provider-specific argument aliases when needed, and recording extra tool-call metadata through the existing hook.

Update documentation and import-boundary expectations to describe `providers/transports/openai_chat/` and `providers/transports/anthropic_messages/` as the transport family locations. The architecture documentation should explain that these packages own thin transport bases plus per-request stream runners and transport-specific recovery/parsing helpers. Update the project version metadata to the next patch version.
