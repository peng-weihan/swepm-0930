Pinot’s transform function evaluator APIs are currently tied to the segment-local module, which makes them unavailable to components that should not depend on segment-local and causes duplicated evaluator state when Groovy support is exposed from more than one package. Refactor the function evaluator API and shared evaluator implementations into stable shared packages while preserving compatibility for existing callers.

The `FunctionEvaluator` interface should be available from `org.apache.pinot.spi.function.FunctionEvaluator` in `pinot-spi`. It must expose the existing evaluator contract: `List<String> getArguments()`, `Object evaluate(GenericRow genericRow)`, and `Object evaluate(Object[] values)`, where `GenericRow` is `org.apache.pinot.spi.data.readers.GenericRow`. The interface should not depend on segment-local classes, and its documentation should make clear that implementations are not required to be thread-safe.

The canonical shared evaluator implementations should live in `pinot-common` under `org.apache.pinot.common.evaluator`. This includes `FunctionEvaluatorFactory`, `InbuiltFunctionEvaluator`, `GroovyFunctionEvaluator`, `GroovyStaticAnalyzerConfig`, and `TimeSpecFunctionEvaluator`. First-party code and tests that directly use these evaluators should import the canonical `org.apache.pinot.common.evaluator.*` classes and the SPI `org.apache.pinot.spi.function.FunctionEvaluator` interface instead of `org.apache.pinot.segment.local.function.*`.

`FunctionEvaluatorFactory` in `org.apache.pinot.common.evaluator` must preserve the existing behavior for creating evaluators. `getExpressionEvaluator(String transformExpression)` should return a Groovy evaluator when the expression starts with the Groovy expression prefix and otherwise return an inbuilt evaluator. `getExpressionEvaluator(FieldSpec fieldSpec)` should continue to support schema `transformFunction` expressions, legacy `TIME` field conversions via `TimeSpecFunctionEvaluator` when incoming and outgoing granularities differ, default Avro map handling for columns ending in `__KEYS` and `__VALUES`, and return `null` when no evaluator is needed. The existing error behavior should be preserved, including wrapping transform construction failures with a message containing `Caught exception while constructing expression evaluator for transform expression: ... of column: ...`, and rejecting invalid time specs where incoming and outgoing specs differ but have the same name with `Invalid timeSpec - Incoming and outgoing field specs are different, but name ... is same`.

Groovy evaluator behavior and configuration must remain unchanged after the move. `GroovyFunctionEvaluator` should continue to recognize expressions of the form `Groovy({expression}, arg1, arg2...)`, expose the same static APIs such as `getGroovyExpressionPrefix()`, `parseGroovyScript(...)`, and `setGroovyStaticAnalyzerConfig(...)`, and use a single shared static analyzer configuration state from the canonical implementation. Broker query validation and ingestion transforms should configure and validate Groovy through `org.apache.pinot.common.evaluator.GroovyFunctionEvaluator` and `GroovyStaticAnalyzerConfig`.

Existing public classes in `org.apache.pinot.segment.local.function` must remain source/binary compatible for users during the transition. The legacy `FunctionEvaluatorFactory`, `GroovyFunctionEvaluator`, `GroovyStaticAnalyzerConfig`, `InbuiltFunctionEvaluator`, and `TimeSpecFunctionEvaluator` APIs should continue to compile and work, but should delegate to or extend the canonical implementations so behavior and Groovy sandbox/static-analyzer state are not duplicated. In particular, calling `org.apache.pinot.segment.local.function.FunctionEvaluatorFactory.getExpressionEvaluator("reverse(testColumn)")` should return an evaluator that is an instance of `org.apache.pinot.common.evaluator.InbuiltFunctionEvaluator`, and evaluating it against a `GenericRow` containing `testColumn = "value"` should return `"eulav"`. Calling the legacy Groovy APIs should still allow `GroovyStaticAnalyzerConfig.createDefault()`, `GroovyFunctionEvaluator.setGroovyStaticAnalyzerConfig(...)`, `GroovyFunctionEvaluator.parseGroovyScript("Groovy({a + 1}, a)")`, and `FunctionEvaluatorFactory.getExpressionEvaluator("Groovy({a + 1}, a)")`; the returned evaluator should be backed by `org.apache.pinot.common.evaluator.GroovyFunctionEvaluator` and evaluating it with `new Object[]{1}` should return `2`.

All Pinot modules that evaluate ingestion transform functions, filter functions, custom function enrichers, schema/default-column transforms, table config validation, broker Groovy validation, UDF tests, and core scalar function tests should use the new shared packages without introducing unnecessary direct dependencies on segment-local.
