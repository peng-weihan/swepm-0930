The Word add-in chat runtime should not inject the active Word document body directly into the system prompt. When `POST /word-chat` receives `document_context`, the system prompt should still include the Word add-in instructions and active document edit protocol, but it must not contain the raw document text. Instead, the active document should be exposed as an available document with `doc_id` `"active-word-document"` and filename `"Active Word document"` so the model can decide whether to inspect it.

The Word chat system instructions should tell the model that, when available, the active Word document is listed under available documents as `"active-word-document"`, that it should call `read_document` with that `doc_id` only when it needs to inspect, summarize, quote, or change the active document, and that it must not assume it knows the document contents before `read_document` returns in the current response. Greetings or unrelated general questions should not require reading the active document.

The `read_document` tool must support request-scoped in-memory document text for the active Word document. Reading `"active-word-document"` should return the supplied `document_context`, emit the normal document read lifecycle events such as `doc_read_start` and `doc_read`, and record the read using the filename `"Active Word document"` without a stored document id. Tool output containing the inline Word text must still be nonce-fenced using the existing spotlight/untrusted-content mechanism before reaching the model.

`find_in_document` must not be allowed to search the request-scoped active Word document before it has gone through the fenced `read_document` path. If called with `doc_id` `"active-word-document"` while that document is represented by inline request text, it should return a tool result with `ok: false`, an error message stating that request-scoped documents must be opened with `read_document` before they can be searched, and a `next_required_action` telling the model to call `read_document` with the active document id. It must not return raw snippets from the inline document or emit document search/read activity for this rejected call.

The `read_document` tool schema and descriptions should refer to available documents generally, not only uploaded attachments, and should document that valid ids include `"active-word-document"`.

Word chats should remain document-scoped and must not expose CourtListener/legal research tooling. Even if the user has `legal_research_us` enabled and a CourtListener API key configured, `/word-chat` should call message building and streaming with research tools disabled, and the streaming arguments should not include the CourtListener API key.
