The runtime should avoid repeatedly constructing identical object shapes for built-in objects that always have the same fixed set of named properties. Common built-in shapes such as those used for function objects, closure/function instances, mapped and unmapped arguments objects, iterator result objects, property descriptor objects, string wrapper objects, arrays with standard layout, and similar runtime-created objects should be cached per `Realm` and reused when creating new objects in that realm.

Object creation paths that use one of these common fixed layouts should still produce exactly the same JavaScript-visible behavior as before. Property names, property order, descriptors, prototypes, accessors, and exotic behavior must remain correct. For example, arguments objects must still expose the correct non-enumerable `length`, `@@iterator`, and `callee` properties; unmapped arguments objects must still use the throwing `%ThrowTypeError%` accessor for `callee`; mapped arguments objects must still map indexed properties through their exotic `[[DefineOwnProperty]]`; arrays must still reject out-of-range lengths with `RangeError: array length out of range`; property descriptor objects returned by descriptor conversion must still contain the expected `value`/`writable` or `get`/`set` plus `enumerable` and `configurable` properties; and string wrapper objects must still expose the correct `length`.

The cached shapes must be realm-specific, because prototypes and intrinsics are realm-specific. Creating a new `Realm` should initialize its common-shape cache after the realm’s intrinsics are available, and garbage collection must continue to trace any cached shape pointers held by the realm.

Add a fast initialization path for objects whose shape already contains the complete fixed property layout. This path should allow all named property values to be installed at once, while preserving the existing property descriptors encoded by the shape. It should only be used for freshly allocated objects whose named property storage has not yet been populated and whose shape has the expected number of fixed properties.

Update the array creation API so callers can distinguish between creating an array with the default realm array prototype, creating one with an explicit optional prototype, and creating one from a cached common shape. Existing behavior of `array_create` should be preserved, while internal callers such as the test shell’s global `arguments` array installation should be able to request the default array shape through an explicit `ArrayCreateShape::Default` mode.

The refactor should not change JavaScript semantics or test-shell behavior. In particular, the test shell should continue to install command-line script arguments as a global `arguments` array, and file-read failures should continue to be reported as syntax errors with messages of the form `failed to read <path>`.
