The project currently keeps most of its application code under public `pkg/...` packages, including configuration/package models, environment handling, GitHub helpers, state handling, templates, logging, update logic, and other helpers. This makes the package structure overly broad and exposes implementation-only APIs as public packages. Refactor the repository so these application internals live under `internal/...` packages instead, while preserving the existing CLI behavior.

The former `pkg/config` package should become the internal package responsible for afx package/configuration types and helpers, importable as `github.com/babarot/afx/internal/pkg`. Existing types and functions such as `Package`, `Config`, `Main`, `DefaultMain`, `GitHub`, `Gist`, `HTTP`, `Local`, `Read`, `Validate`, `Sort`, `WalkDir`, `CreateDirIfNotExist`, `HasGitHubReleaseBlock`, and `HasSudoInCommandBuildSteps` must remain available from that internal package. Tests that previously belonged to `pkg/config` should run in package `pkg` under `internal/pkg`.

Other former `pkg/...` packages should also be moved under `internal/...`, and all imports throughout the CLI and tests should use the new internal paths, for example `github.com/babarot/afx/internal/env`, `internal/errors`, `internal/github`, `internal/state`, `internal/update`, `internal/printers`, `internal/logging`, `internal/data`, `internal/templates`, and `internal/helpers/...`.

The `cmd` package must continue to work with the refactored package types. `metaCmd` should store package data using `internal/pkg` types, and its helper methods must continue to behave the same: `GetPackage(state.Resource)` returns the matching package by resource name or `nil` when not found; `GetPackages([]state.Resource)` returns packages in the same order as the given resources; and `GetConfig()` merges all loaded config fragments into one config, preserving any non-nil `Main` and appending all `GitHub`, `Gist`, `HTTP`, and `Local` entries.

The duplicated concurrent execution/progress handling in `install` and `check` should be factored out into an internal runner package used by both commands. The user-visible behavior should remain the same: `afx install` still runs each selected package’s `Install(ctx, completion)` method, performs cleanup via `Uninstall(ctx)` when install fails and the package was not previously installed, refreshes the environment after an error, and returns combined errors; `afx check` still runs each selected package’s `Check(ctx, completion)` method, reports progress, refreshes the environment after an error, and returns combined errors. Both commands must still support cancellation via context and preserve the previous concurrency limit/progress behavior.

The tilde expansion helper should be available from `github.com/babarot/afx/internal/helpers/path` as `ExpandTilda`. It must expand `"~/foo"` to `$HOME/foo`, expand `"~"` to `$HOME`, leave absolute paths such as `"/absolute/path"` unchanged, leave the empty string unchanged, and leave `"~/foo"` unchanged when `$HOME` is empty.

After the refactor, the repository should build and all tests should pass using the new internal package layout, without relying on the old `github.com/babarot/afx/pkg/...` import paths.
