Refactor the proxy fetching subsystem so proxy sources are independent, discoverable fetcher plugins instead of static methods on the monolithic `fetcher/proxyFetcher.py`.

The project currently keeps all proxy source implementations in `ProxyFetcher` and selects them through the static `setting.PROXY_FETCHER` list of method names such as `freeProxy01`, `freeProxy02`, etc. This makes the file large, makes individual sources difficult to debug or update independently, and requires manual configuration whenever sources are added or removed. The scheduler in `helper/fetch.py` should no longer depend on `fetcher.proxyFetcher.ProxyFetcher` or static method names.

Introduce a common `fetcher.baseFetcher.BaseFetcher` class for proxy source implementations. Each source class should declare a unique `name`, a source `url`, an `enabled` flag defaulting to enabled, and implement `fetch(self)` as a generator yielding proxy strings in `"host:port"` format. The base class should also provide reusable parsing helpers visible to tests: `parseProxiesFromText(text)`, `parseProxiesFromJson(data)`, `parseProxiesFromTree(tree)`, and `yieldUniqueProxies(proxies)`. These helpers must handle common proxy extraction cases, including plain text containing `1.2.3.4:8080` or `1.2.3.4 8080`, nested JSON structures using keys such as `proxy`, `addr`, `address`, `ip`, `host`, `server`, and `port`, and lxml table rows containing IP and port cells. Empty or missing input should return an empty list.

Move the existing proxy sources out of `fetcher/proxyFetcher.py` into separate modules under `fetcher/sources/`. Each module should define one `BaseFetcher` subclass and be independently runnable for debugging. The existing source behavior should be preserved, but sources should now be represented with descriptive class names such as `ZdayeFetcher`, `ScdnFetcher`, `KuaidailiFetcher`, `IhuanFetcher`, `FreeProxyListFetcher`, and the other migrated proxy sources. Calling `SomeFetcher().fetch()` should yield the same style of proxy strings as before.

Update proxy discovery and scheduling so `helper/fetch.py` dynamically scans `fetcher/sources/` for subclasses of `BaseFetcher`. Discovery should include only classes with a non-empty `name`, `enabled=True`, and not present in the configured exclusion list. The returned active fetcher class names should be sorted for stable output. Fetcher modules should be imported dynamically, and already-imported modules should be reloadable so changes to fetcher source files can be picked up at runtime. The threaded fetch scheduler should instantiate each discovered fetcher class and call its `fetch()` method, store sources using the fetcher’s `name`, and log the active fetcher list at the start of each run in the format `ProxyFetch : active fetchers [...]`.

Replace the old static `setting.PROXY_FETCHER` configuration with `setting.PROXY_FETCHER_EXCLUDE = []`. `ConfigHandler` should expose this as `fetcherExclude`, reloading `setting.py` so configuration changes are picked up. The launcher’s configuration display should describe proxy fetching as auto-scan based and show the exclusion list when present.

Add a new CLI command to `proxyPool.py`: `show`. Running the command should print the currently active fetcher classes discovered from `fetcher/sources/`, for example starting with `Active fetchers (<count>):` followed by one `  - <FetcherClassName>` line per active source. If any classes are excluded through `PROXY_FETCHER_EXCLUDE`, the command should also print an `Excluded: ...` line.

After the refactor, `fetcher/proxyFetcher.py` should no longer be required, the scheduler should not reference the old `ProxyFetcher` class or `freeProxyXX` method names, and all migrated fetchers should still be usable through the dynamic auto-scan mechanism.
